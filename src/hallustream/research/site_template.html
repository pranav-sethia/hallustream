Catch an AI making things up while it writes

HalluStream reads a language model's hidden states as each word is generated and flags the names, dates and titles it is probably inventing. No second model, no web search, about 5% extra time.

Read the code Run it free in Colab

Built with PyTorch and Hugging Face Transformers on Qwen3-4B, GLiNER, Gemini as the fact checker, and Modal GPUs.

    Plugged into a 2026 method, it beat that method's own detector

    SHARS (ICML 2026) rewrites an answer sentence by sentence. For each fact, it asks a detector whether the model is making it up. Its detector re-asks the model about every fact several times and checks if the answers agree. I swapped in the probe and changed nothing else, then tested on 60 people held out from all tuning, with the analysis written down before the run.

    Lower is fewer false claims, further left is cheaper. Detection time is on a log scale, measured on one L4 GPU.

    Read the answers

    The same request, “Tell me a bio of …”, answered three ways. Dotted text is supported by the person's Wikipedia page; struck-through text is not. Hover or tap it for the fact checker's note.

    SHARS removes or rewrites the sentences the detector doubts, so its answers come out shorter and plainer: fewer invented facts, not more facts. These are 4 of the 60 test people; the numbers above cover all 60.

    How it reads the model

    When a model writes a fact it does not really know, its internal state looks different from when it does. A small linear classifier, trained on about 20,000 fact-checked answers, learns to read that difference from one middle layer.

    The model writes

    Qwen3-4B generates normally. Nothing extra is generated or looked up.

    Layer 21 is read

    Each new token's hidden state, 2,560 numbers, is taken from layer 21 of 36, the layer a sweep over all of them found best.

    The probe scores it

    One dot product per token. When a sentence ends, the details in it get a risk from their tokens.

    Risky details are flagged

    Names, dates, numbers and titles above the threshold light up, while the answer is still being written.

    Choose how cautious it is

    A risk is the estimated chance a detail is made up, and it holds up: details given 90–100% risk turned out false 93% of the time. Where to draw the line is a trade-off between catching more errors and wrongly flagging true facts. Measured on text never used to build it.

    Stated risk against how often those details were actually false. On the diagonal means the risk can be taken at face value.

    Not just biographies

    How often a made-up detail gets a higher risk than a true one, where 50% is a coin flip. Compared with the model's own confidence in each word, the usual cheap signal.

    Run it

    A pip package with a command line and a Python API. It needs a GPU or an Apple Silicon Mac for Qwen3-4B, or the free Colab notebook.

    # install pip install "hallustream[entities] @ git+https://github.com/pranav-sethia/hallustream" # ask, with likely made-up details highlighted as each sentence is checked hallustream "Tell me about A Caribbean Mystery."
    hallustream chat

    The same, in a conversation.

    hallustream score "question" answer.txt

    Check an answer the model already wrote.

    hallustream batch prompts.jsonl

    Check a whole file and get JSON lines back.

    Detector.from_pretrained("qwen3-4b")

    Or from Python: generate, score or stream.

    How it was tested

    • Written down first

      Every test's settings, metrics and pass bars were committed before its results existed.

    • Held out

      Settings were chosen on separate people. Each test set was scored once.

    • A checked fact checker

      Gemini reading Wikipedia agreed with FActScore's human labels at 89% balanced accuracy on 11,049 facts.

    • No leaks

      None of the test people appear in the probe's training data.

    • Failures reported

      Three ideas were stopped by their own rules: rewriting with retrieval, the probe as a training reward, and checking larger models' text. See the results.
